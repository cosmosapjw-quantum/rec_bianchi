# R3O: 재시작 메모리와 독립적인 시간 격자 시작

## 연구 범위와 재사용

이 문서는 원본 HyRec Oct2012의 고정된 연산자를 유지하면서 h2 저적색편이
연속 적분과 독립 h4 초기화를 구현하는 국소 연구를 정리한다. h2는
`4.245e-5`, h4는 `2.1225e-5`이다. 원본 ZIP의 SHA256은
`48cd597519606cdafd0ee6405b781d28467cd323278d16596055a8d0577a1d27`이다.
정확한 단계 guard와 predictor는 이 ZIP의 `history.c`를 기준으로 한다.
HyRec의 EMLA/복사전달 구성에 대한 논문 근거는
[Ali-Haïmoud & Hirata, arXiv:1011.3758](https://arxiv.org/abs/1011.3758)이다.

PR107에서 검토된 실제 h2 U6 5210-step 결과와 PR108의 원본 4점 보간,
격자 비교 및 조건부 2차 정확도 분석은 재사용한다. 원본 h의 U8 완료
이력도 원격 전체 바이트 해시가 일치하는 아카이브에서 복구했다.
이들은 이번에 다시 수행한 production 계산이 아니다.

## 재시작의 충분한 상태

원본 predictor는 현재 미분과 두 입력 전 미분을 사용한다.

\[
Y_{n+1}=Y_n+h\left(\frac54F_n-\frac14F_{n-2}\right).
\]

입력 상태 n에서 `prev=F[n-1]`, `prev2=F[n-2]`이며, 수용 후
`(prev2, prev)`를 `(prev, F[n])`으로 회전한다. 따라서 h2 저적색편이
재시작에는 상태 `(xe,Tm)`, H/열 미분 각각의 두 꼬리, 입력 격자 인덱스,
흡수적인 Peebles 전환 기록이 필요하다. 동일한 초기 증강 상태와 고정된
연산자에서 이 재귀식을 반복하면 정확한 산술에서 연속 적분과 일치한다.
이를 C/Python의 무조건적인 바이트 일치로 해석하지 않는다.

단계 경계에서 이전 미분을 새 단계의 연산자로 다시 계산하면 원본
알고리즘이 바뀐다. FULL→EMLA 및 EMLA→Peebles의 첫 두 갱신에도 기존
단계가 소유한 미분 꼬리를 그대로 사용한다. FULL에서는 추가로 수용된
과거 광자 열과 post-Saha 상태가 필요하다.

고정된 affine RHS `F(Y)=LY+b`에서 상태는 정확하고 저장된 미분만
`delta_2`, `delta_1`만큼 오염되었다면,

\[
e_1=-\frac h4\delta_2,\qquad
e_2=\left(I+\frac{5h}{4}L\right)e_1-\frac h4\delta_1.
\]

두 번의 회전 후 잘못 저장된 미분 자체는 사라져도 이미 유도된 상태
오차는 남는다. Lipschitz 상수 ell이 유효한 고정 분기에서는
`||e2|| <= (1+5 h ell/4) h ||delta2||/4 + h ||delta1||/4`이다.
독립 R6 검토의 유리수 계산이 이 항등식을 별도로 확인했다.
Wolfram 도구가 반환하지 못한 논리 동치 판정은 외부 PASS로 세지 않는다.
상세 호출 결과는 `receipts/SOURCES.json`에 보존한다.

## 각 격자의 floor 식과 입력 시각의 단계 전환

\[
z_i=8001\exp(-h_\ell i)-1,\quad
i_{H0}=\left\lfloor1+\frac{\log(k_BT_0\,8001/(f_s^2m_rT_{R,max}))}{h_\ell}\right\rfloor,
\quad N_z=\left\lfloor2+\frac{\log8001}{h_\ell}\right\rfloor.
\]

| 격자 | 간격 | izH0 | 마지막 출력 인덱스 | TR_MIN 첫 거짓 입력* |
|---|---:|---:|---:|---:|
| h | 8.49e-5 | 18223 | 105858 | 72466 |
| h2 | 4.245e-5 | 36446 | 211716 | 144931 |
| h4 | 2.1225e-5 | 72892 | 423431 | 289861 |

*온도비 `Tm/Tr > 0.1` 조건이 그때까지 유지된 경우이다. 물리적인 새
h2/h4 전 구간에서 먼저 실패할 guard를 아직 계산하지 않았다.

단계는 출력 인덱스가 아니라 RHS를 평가하는 입력 상태에서 선택된다.
h2 입력 144930의 Tr은 0.004000029855176720 eV이고, 144931에서는
0.003999860057513351 eV이다. 제어된 온도비 조건에서
144930→144931은 EMLA, 144931→144932는 Peebles이다. 원본 h 이벤트
72466을 단순히 두 배 하면 h2 이벤트를 한 입력 늦게 배치한다.

h2 U6의 경계는 58389이다. 여기부터 마지막 출력 211716까지는
153327-step이 필요하다. 마지막 출력의 약간 음수인 z는 원본 z=0
4점 보간용 상태이며, 음수 z에서 새 RHS를 평가하지 않는다.

독립 R6에서 확인한 종료 재시작 결함은 수정했다. 마지막 1~2단계만
남은 checkpoint는 실제 4점 상태가 없으므로
`SOURCE_END_REACHED_INCOMPLETE_Z0_STENCIL`을 반환한다. 3단계로 실제
4개 상태가 모이면 원본 C와 같은 보간을 수행한다. 미분 꼬리에서
누락된 과거 상태를 만들어 내지 않는다. 자동 CLI resume는 별개의
미구현 기능이며, 이 수정으로 구현되었다고 주장하지 않는다.

## h4의 독립성과 광자 인과성

h4는 자체 HeIII Saha→HeII 이력을 Python으로 생성하고 자체 중심
차분에서 H/He predictor 꼬리를 얻는다. 원본 C도 별도로 자체 이력을
생성한다. Python 진화 상태에 C 궤적이나 h2 checkpoint를 주입하지
않는다. h2에서 재사용하는 것은 시간 간격을 소유하지 않는 원본
스칼라 식이며, 전역 DLNA monkeypatch는 사용하지 않는다.

원본 311개 에너지와 Lyman 연결을 읽은 독립 검토에서 313개 링크의
최소 로그 에너지 간격은 `8.49527887747085e-5 = 4.002487103637621 h4`
였다. 현재 h4 시작은 수용된 과거 열만 참조하고 post-Saha 시험 열은
이력에 넣지 않는다. 8개 FULL step 후 endpoint 72900의 predictor는
입력 72898,72899의 미분을 소유한다.

## 열 연산자에 대한 제한된 안정성 해석

원본 열 RHS는 다음 분기를 갖는다.

\[
F_T=\begin{cases}
-T_r,&T_r/T_m-1<10^{-10},\\
-2T_m+A(T_r-T_m),&\text{그 외},
\end{cases}\qquad
A=\frac{f_s^2}{m_r^3}\frac{4.91466895548409\times10^{-22}T_r^4}{H}
\frac{x_e}{1+x_e+f_{He}}\ge0.
\]

Tr, xe, H를 동결한 두 번째 분기에서만 `lambda=-2-A`이다. 기존
스칼라 엄격 감쇠 조건 `-2<h lambda<0`은 이 분기에서
`h(2+A)<2`를 준다. 첫 번째 분기의 Tm 미분은 동결 조건에서 0이다.
분기 스위치와 결합된 비선형 궤적 전체에 이 스칼라 조건을 확대하지
않는다. 구현은 원본의 분기와 부등식을 그대로 보존한다.

## 실제 검증이 지지하는 범위

- 새 h2 실행: 실제 검토된 U6 경계부터 16개 EMLA step, 원본 C 같은-h
  비교. R6 종료 상태 수정 후 동일한 코드에 대해 smoke를 새로 수행했다.
- 새 h4 실행: 독립적인 72893개 He 행과 8개 FULL step을 원본 C와 비교.
- 원본 h 입력: 기존 105859개 source-grid 상태를 복구해 비교기에 연결.
  기존 8001개 integer-z 최대 오차는 source-grid 각 노드의 오차 상한이
  아니므로 노드별 parity는 UNKNOWN으로 유지한다.
- h+h2 부분 이력은 세 격자 비교의 충분한 입력이 아니며,
  `INSUFFICIENT_LEVELS`를 유지한다.

실행 수치와 코드 정체성은 `EVIDENCE.json`, 독립 검토는
`review/R6_PHYS_MATH.md` 및 종료 수정 receipt에 연결한다.
전체 h2 저적색편이, h4 후속 전 구간, 전역 h/h2/h4 물리 수렴성,
production speedup은 아직 미실행이다. 원본 h `HOLD_9_FAIL`,
h2 `HOLD_8_FAIL`, 닫힌 과거 비용, `REI_activation=false`를 유지한다.
