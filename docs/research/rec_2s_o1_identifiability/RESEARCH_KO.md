## 범위와 기준

고정 부모는 PR #67의 `dc9e9e9394eba314afa13e6db1b0811257e3be55`, tree는 `a12bdda27717a9b0f7a182e86bf6c3d081087ecc`다. 기존 PR #63 어댑터, PR #65의 140행 추적, PR #66/#67의 O2/O3 계산을 재구현하거나 재검증하지 않는다. 이 연구는 O2/O3의 책임자 선택과 독립적인 O1 자료 조사다. 원래 O1–O6의 상태와 선택 필드는 변경하지 않는다.

## 원 논문과 원본 자료가 뒷받침하는 것

Ali-Haimoud–Hirata, arXiv:1011.3758v2, V A, 식 (66)–(67), 인쇄 13쪽은 미분 전이율을 정규화된 좁은 spike의 합으로 바꾸고 각 계수를 해당 주파수 영역의 적분으로 정의한다. 같은 논문의 식 (73)은 spike profile에 대한 occupation 평균을 정의한다. 이번에는 원 논문 해당 페이지의 PDF 렌더링을 직접 확인했다.

https://arxiv.org/pdf/1011.3758

이 사실은 원본이 연속 방정식을 이산화한다는 근거이지, 우리 저장소의 다섯 열만으로 각 I_b의 경계나 커널 생성 절차를 복원했다는 근거가 아니다. PR #65의 `SOURCE_EXCERPTS.txt`와 `OWNER_REVIEW_CONTRACT.json`이 특정 보관본의 직접 근거다. 현대 HYREC-2 파일은 보관된 2012 표의 대체물로 사용하지 않는다. SciSpace 검색은 이 논문을 찾는 데만 사용했으며, 검색 결과의 자동 요약이나 날짜를 원본 바이트의 근거로 삼지 않는다.

## 중요한 구분: 이산 모델의 정의와 연속 모델의 인증

주어진 중심 E_b와 적분계수 A_b는 이산 선형 범함수

    Q[F] = sum_b A_b F(E_b)

를 정의하기에 충분하다. 그러므로 I_b를 모른다는 이유만으로 이미 정의된 이산 계수식의 평가나 원본 재현을 불가능하다고 해서는 안 된다. 다만 Q가 어떤 연속 커널·구간에서 생성됐는지, 임의 비평형 복사장에 대한 오차가 얼마인지, 물리적인 photon cell 측도가 무엇인지는 별도다. 이산 계수 평가가 원본 전체 history의 재현이라는 뜻도 아니다.

연속적인 후보 표현을

    R_b[F] = integral_{I_b} K(E) F(E) dE,
    A_b = integral_{I_b} K(E) dE

라고 하자. K>=0인 자발 2s 계수의 유한 구간을 가정한다. 원본의 A_b와 E_b만으로 K 또는 I_b 전체가 정해진다는 추가 가정은 하지 않는다.

## 정확한 제조 반례: 질량과 중심까지 같아도 두 광자 source는 다르다

실제 원자 커널이 아닌 독립적인 식별성 반례다. x in [0,1], 0<epsilon<1에서

    P(x) = 6x^2-6x+1,
    k_plus(x) = 1+epsilon P(x),
    k_minus(x) = 1-epsilon P(x).

P의 범위는 [-1/2,1]이므로 두 커널은 양수다. 두 커널 모두 적분 1, 첫 모멘트 1/2를 가진다. 그러나 둘째 모멘트는 1/3 +/- epsilon/30이다. 즉 구간 자체와 정확한 중심까지 더 알려 주더라도 영차·일차 자료만으로 일반적인 source 적분을 정할 수 없다.

쌍반응의 제조 복사장으로 f_t=f_c=x, x_u=1/4, x_g=3/4를 택하면

    F(x) = x_u(1+x)^2-x_g x^2
         = 1/4+x/2-x^2/2.

동일한 정규화 A=1 s^-1에서

    R_plus/A  = 1/3-epsilon/60,
    R_minus/A = 1/3+epsilon/60.

따라서 epsilon=1/2이면 R_plus/A=13/40, R_minus/A=41/120이고 차이는 1/60이다. 같은 중심에서의 spike 값은 F(1/2)=3/8이다. 이는 실제 HyRec 오차 수치가 아니며 기존 표의 두 대체 커널을 제안하는 것도 아니다. E_t=E21(1+x)/2, E_c=E21(1-x)/2로 읽으면 고에너지/companion 에너지 관계와 양립한다. 이 제조 선택을 원본 입력에 기록하지 않는다.

## 조건부 오차 경계

새 물리 상수나 tolerance를 정하지 않고 필요한 정보의 종류를 유도한다. I_b가 알려져 있고 F가 Lipschitz 연속이며 L_b=sup_{I_b}|F'|라면

    |R_b-A_b F(E_b)| <= L_b integral K(E)|E-E_b| dE
                       <= A_b L_b Delta_b,
    Delta_b = sup_{E in I_b}|E-E_b|.

F가 C^2이고 M_b=sup|F''|이면

    |R_b-A_b F(E_b)|
      <= |F'(E_b)| |m1_b| + (M_b/2) m2_b,
    m1_b = integral K(E)(E-E_b) dE,
    m2_b = integral K(E)(E-E_b)^2 dE.

E_b가 K의 실제 무게중심일 때만 m1_b=0이다. 원본 spike 중심이 그 무게중심이라고 확인되지 않은 상태에서 첫 항을 버리지 않는다. 검산기는 k(x)=2x, E_b=1/2, F=x의 반례를 포함한다. 둘째 미분은 0이지만 실제 차이는 1/6이다.

위의 대칭 제조 커널과 이차 F에서는 m1=0이며 remainder의 크기가 m2/2와 정확히 같다. 이는 조건부 경계의 검산이지 실제 표에서 m2를 얻었다는 뜻이 아니다. 불연속 source나 무제한 미분에서는 이 경계를 주장하지 않는다.

단위: E를 J로 쓰면 K는 s^-1 J^-1, A는 s^-1, population/occupation으로 구성한 F는 무차원, m1은 J s^-1, m2는 J^2 s^-1이다. 모든 오차 항은 수소 원자당 s^-1인 source rate와 맞는다. 고정 프레임의 순간 충돌항이며 metric (-,+,+,+)를 바꾸거나 c,hbar,k_B를 자연단위로 제거하지 않는다.

## 구간을 알면 복원할 수 있는 조건도 분리한다

명시적 K, 연속적으로 인접한 구간이라는 규칙, 시작 경계 E_0, 원래의 정규화가 모두 주어지고 K>0 a.e.라면

    G(E)=integral_{E_0}^E K(u) du,
    E_j=G^{-1}(sum_{b<j} A_b)

로 경계를 복원할 수 있다. 이것은 가능한 조건부 경로이며, '영원히 복원 불가능'이라는 주장이 아니다. 실제 원본이 이 partition 규칙으로 생성됐는지와 저장 계수 반올림·정규화의 영향은 별도 검증해야 한다. 보관된 2012 표에 이 방법을 적용하지 않는다.

## photon 상태 측도와 전이계수는 다른 측도다

두 편광을 포함하고 각도 가중치 합이 1인 full-solid-angle convention의 실제 cell이 주어졌을 때

    mu_i = 8*pi/(3*h^3*c^3) * (E_hi^3-E_lo^3), h=2*pi*hbar

이다. 이는 photon state counting이며, K(E)dE는 전이율 측도다. A_b가 s^-1이라는 것만으로 m^-3의 mu_i를 만들 수 없다. 새 photon cell 경계·각도·편광 convention은 여기서 선택하지 않는다. 분배 map의 number/energy 보존만으로 B를 고를 수 없다는 기존 PR #61/#63 결과도 그대로다.

## 실행 및 감사 계획

허용 경로는 이 연구 디렉터리와 `.github/workflows/rec-2s-o1-identifiability.yml`뿐이다. 읽기 전용 hosted 실행은 독립 Fraction 다항식 적분과 SymPy 적분을 비교하고, 질량·중심만 사용하는 mutation 및 centroid 항 누락을 검출한다. 원본 ZIP은 새 O1 구성원 조사 목적으로 해시 검증·메모리 읽기만 한다. C/원본 history/production tests와 기존 O2/O3 checker는 실행하지 않는다. 출력은 Git 밖에 남기고, 수치 결과와 실제 사용한 source SHA/tree를 후속 완료 기록에 보존한다.

수학 관점: 양의 커널 범위, 정확한 모멘트, 단위, 조건부 경계와 가정 누락을 검사한다. 코드 관점: 원본 무변경, 실제 실행 identity, 독립 계산, 실패 보존을 검사한다. 같은 작성자의 두 관점이며 독립 심사 두 사람으로 표시하지 않는다.

로컬 container와 Python은 각각 process 시작 전 ClientError였다. WolframContext도 MCP SSE HTTP404로 실패했다. 이를 수학 실패로 처리하지 않고 새 hosted 경로를 한 번 사용한다. 새 그림이 생성되더라도 실제 렌더링을 읽기 전에는 시각 검토 완료라 부르지 않는다.
