# REC–REI IGM work-selection policy (bounded overlay; effective on this draft branch only)

**Authority:** Existing source locks, original HyRec physics, 35 Hz failures, 88-node REI canonical DAG, REC 313-cell H5 physical contract, budget and no-merge policies prevail. This file changes **research work selection**, not scientific acceptance. This proposed branch policy is not active on `main` or in `rei_bianchi` until separately integrated.

1. **Start from an observable.** Name the REI consumer, source owner, accepted input identity and which term in `x_HII`, `T`, photon/thermal/work ledger, or tau/visibility can change. If none is identified, call the task `AUXILIARY` or `OPEN_SCIENCE`, not `CENTRAL_PROGRESS`.
2. **Choose the shortest dependency path.** Reuse the last accepted source/trajectory. Prioritize actual first coupled interval or REC→REI consumer binding, H5 genuine physical coverage, or a known physical blocker over another adjacent source/covariance/HD sensitivity study. Do not force H5/HD into an H/He-only S0 lane if not consumed.
3. **No empty closure theatre.** A plan, R/C-20/20, plot, source row, JSON, PR, checksum, CI PASS or non-author same-context review is not a canonical admission. Show both `(canonical completed/88)` and `(REC H5 physical completed/313)` after a stage, even if unchanged. Explicitly report accepted coupled intervals and named observables, including `0/NOT_RUN`.
4. **Protect freedom to investigate, but demand a reason.** A genuinely novel independent result, falsifying counterexample or newly sourced physical input may be done as bounded auxiliary work. After two adjacent auxiliary-only science units with no new consumer/defect resolution, the next selection must explicitly reassess the shortest primary path or stop with a specific blocker. This is a choice rule, not a blanket ban or new science gate.
5. **Separate scope of blockers.** Original HD 35 Hz `FAIL7/8` applies to affected HD spectroscopy/energy-interface use, not automatically to H/He S0. H5 `0/313` blocks physical H5/consumer claims. REI `NO_MORE_IVPS` blocks new REI IVPs under the inherited budget. Unchanged repository-wide CI whitespace failure is a packaging/integration failure, not new physics PASS/FAIL; never silently loosen the verifier or rewrite immutable source artifacts.
6. **One verified physical output beats ten meta-loops.** Each bounded task has at most one primary test and one justified fresh adversarial pass. Record the actual scientific delta, exact source/input/owner, version/SHA, observed failure category and next executable action. Do not multiply ledgers, checklists, audits, committees or exploratory DAG nodes as surrogate progress.
7. **Preserve source ownership and production restraint.** No implicit owner swap; no original tolerance relaxation; no merge/force-push; no auto-next; no budget reset; no production/L4 activation; no independent claim from re-used author posterior. If a future genuinely approved admission changes counts, log its separately authorized exact source and evidence instead of editing historical snapshots.
8. **Git/source transparency.** A text-only PR is a receipt, not a runnable archive. Record exactly which code/data reside only in external ZIP, which provider has readback, and whether distinct-author review occurred. Treat remote provider ACK, exact bytes, scientific replay and Git CI as separate axes. Use a standalone draft PR for this policy; no ancestry rewrite.

**Immediate single recommendation:** `REC_REI_HISTORY_CONSUMER_BINDING` is the next *REC-owned* bounded non-IVP science/implementation task. REI's `REI-F05` full interval remains a separate REI-owned parallel route, not forcibly dependent on REC source acquisition. Nothing here executes either candidate automatically.

**Positive termination:** The next read-only bridge unit closes when it identifies one immutable packet, named consumer and passing parity/ledger check, or records a precise missing required field and a feasible source remedy. If no valid packet exists, do not relabel the absence a theorem; do not launch another HD atlas solely to avoid stopping.
