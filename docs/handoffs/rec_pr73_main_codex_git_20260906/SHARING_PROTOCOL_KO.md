# 주 대화–local Codex Git 기반 양방향 인계

## 사용자 지시와 적용 범위

2026-09-06 사용자는 별도 작업 스레드를 기본 절차에서 제거하고, 주 대화에서 가능한 연구·코드·검토·게시를 수행하며, 실제 로컬 실행이 필요한 부분만 Codex에 맡기도록 지시했다. Codex는 승인 범위의 결함을 자동 수정·재검증한 뒤 주 대화로 직접 반환한다. 추가로 인계 파일과 반환 자료도 가능한 한 Git에 게시하여 사용자가 ZIP을 다운로드하고 다시 업로드할 필요 없이 Codex 출력이나 링크만 전달하도록 요청했다.

이 문서는 그 요청을 REC의 현재 인계에 적용한 기록이다. 전역 하네스 저장소나 모든 프로젝트의 파일을 이미 갱신했다는 뜻은 아니다. 이전 PR73 댓글5559845524의 범위 내 자동 수정 원칙은 유지하고, 그 댓글과 옛 인계문의 'Codex는 원격 push/PR를 하지 않는다'는 제한만 아래의 명시적 결과 게시 허용으로 대체한다. 과거 문서와 실행 기록은 수정하지 않는다.

## 정상 왕복 경로

주 대화가 작업별 인계문을 관련 저장소의 새 branch에 게시한다. 사용자는 고정 commit의 인계문 링크만 Codex에 전달한다. Codex는 해당 파일을 직접 읽고 승인된 작업을 수행하며, 필요한 수정·검증과 반환 인계문을 자기 결과 branch에 게시한다. Codex의 최종 출력에 포함된 PR·commit·반환문서 링크만 주 대화로 전달한다. 주 대화는 연결 도구로 실제 파일과 증거를 읽어 검토한다.

별도 작업 스레드, 수동 ZIP 왕복, 전체 결과의 채팅 붙여넣기는 기본 경로가 아니다. 링크를 받기 전에 작업이 자동 실행되거나 감시되고 있다고 주장하지 않는다. 반대로 작은 요약을 받았다는 이유만으로 연결된 증거를 읽지 않고 수용하지도 않는다.

## 게시 권한과 단일 작성자

이번 과제에서 Codex는 지정한 REC 결과 branch의 생성, 그 branch에 대한 non-force push, 관련 Draft PR 생성·결과 설명 갱신과 게시 후 읽기를 수행할 수 있다. 허용되는 것은 해당 과제의 수정·실행·반환물 공유다. 기존 인계 branch, PR73 branch, main 또는 다른 사람/세션의 branch는 갱신하지 않는다.

주 대화는 인계 branch를, Codex는 결과 branch를 소유한다. 동일 branch의 동시 작성은 피한다. 결과 반환 이후 추가 쓰기가 필요하면 현재 remote head를 확인해 새 명시적 작업으로 진행한다. 이미 동일 결과가 게시됐거나 실행 중이면 중복 실행·중복 PR를 만들지 않는다.

Codex의 게시 성공은 최종 과학적 수용이나 병합 승인이 아니다. 최종 결과 판정, 다음 연구 결정, 필요한 REC Atlassian 동기화는 주 대화가 담당한다. merge, ready 전환, rebase/force-push, 권한·가시성 변경, 타 저장소 mutation은 별도 승인 없이 하지 않는다.

## 반환문서와 접근 가능한 증거

결과 branch에는 최소한 다음을 둔다. 새 범용 하네스나 대형 중복 manifest를 만들지 않고 기존 결과 구조를 재사용한다.

- RETURN_HANDOFF_KO.md: 실제 완료/부분완료/실패, 최초 원인과 수리, 변경 파일, 테스트 결과, 미실행·미확정, 주 대화의 다음 한 작업.
- RESULT.json 및 RETURN_IDENTITY.json 또는 같은 정보를 담은 기존 파일: 인계·기준·실행·결과 identity, 명령·종료 상태·TestID별 결과와 읽을 수 있는 증거 위치.
- 변경된 진단 코드와 직접 관련 검사, 공개 가능한 필수 로그·수치 CSV·그림. 원본과 가공된 사본을 구분한다.

원본 ZIP 또는 대형 이진 bundle만을 유일한 증거로 두지 않는다. 주 대화에서 UTF-8 문서·JSON·CSV·로그를 직접 읽어 결과를 판단할 수 있게 한다. 큰 파일은 이미 승인된 저장 공간이 실제로 사용 가능한 경우에만 별도 저장하고 위치·크기·해시·접근조건·만료 여부를 기록한다. 로컬 절대경로나 존재하지 않는 sandbox URL은 공유 링크가 아니다. 새 업로드 서비스를 임의 도입하지 않는다.

영구 반환 문서는 가변 branch 링크만이 아니라 `blob/<정확한 commit>/<경로>` 링크로 전달한다. 최종 출력의 최소 정보는 저장소, Draft PR URL, 게시 commit/tree, 고정 반환문서 URL, 실제 실행 source commit/tree, 실행 및 게시의 각각의 상태다. 최종 commit 자신의 SHA를 그 commit 내부 문서에 억지로 넣어 순환 갱신하지 않는다. 최종 게시 SHA는 PR 본문·Codex 출력에 쓰고, 문서 안에는 이미 확정된 실행 SHA와 상대 증거 경로를 사용해도 충분하다.

## 원본 보존과 비공개 자료

현재 REC는 공개 저장소다. BASS 비공개 소스, 자격증명, 개인정보, 비공개 데이터와 이를 포함하는 raw 로그·bundle을 공개 REC에 자동 push하지 않는다. 필요한 파일의 identity와 공개 가능한 실행 결과만 공유한다. 비공개 원본의 읽기 권한은 공개 재배포 권한이 아니다.

원본은 적절한 비공개/로컬 위치에 보존한다. 공개 사본에서 민감정보를 제거해야 한다면 사본에 그 사실을 표시하고, 원본과 byte identity를 주장하지 않는다. 미게시 부분이 결과 수용에 필요한 핵심 증거라면 미해결로 드러내며 공개 요약만으로 검증 완료를 선언하지 않는다. 해시는 원본 위치와 변경을 식별하는 수단이지 물리적 진실을 보증하는 수단이 아니다.

## 실패·수정·게시의 구분

같은 목표·허용 경로·보호 불변식 안에서는 실행 → 원인 진단 → 관련 최소 수정 → 표적 회귀검사 → 재실행을 자율적으로 수행한다. 한 수정 회차는 편집 한 번이 아니다. 수정 없이 같은 실패를 반복하는 재시도와, 새 증거에 따른 수정 후 재검증을 구분한다. 실제 자원 상한과 보호된 과학적 의미는 유지한다.

실패나 부분완료도 정직한 checkpoint로 게시할 수 있다. 테스트 실패를 숨기고 PASS를 얻은 뒤에만 게시해야 하는 것은 아니다. 다만 게시 성공, 실행 성공, 과학적 수용, 그림 검토, 전체 CI 결과는 각각 보고한다.

기존 인증 경로로 push가 실패하면 다른 이미 사용 가능한 승인된 GitHub 경로를 확인할 수 있다. 새 토큰 노출, 공개 가시성 전환, 인증을 회피하는 우회 경로는 쓰지 않는다. 게시가 끝내 불가능하면 PUBLICATION_BLOCKED로 기록하고, 가능한 저장된 링크나 최소 반환문을 우선 전달한다. 수동 ZIP 전달은 접근 경로가 실제로 없는 경우의 마지막 대안이지 일상 절차가 아니다.

이 정책 파일의 게시만으로 새 로컬 실행이나 science PASS가 생기지는 않는다. 현재 과제의 보호 상태는 `NO_PASS_REC_PHYSICAL_SPLIT`이다.
