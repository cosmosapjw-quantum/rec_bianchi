## Independent theorem and version-matched API audit

Only three official documentation topics were used, as preregistered.

1. **[SciPy 1.17 `solve_ivp`](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.integrate.solve_ivp.html), event/return/tolerance sections.** Its event search is sign-change based per accepted step and explicitly allows multiple crossings in one step to be missed; `success` only means reaching the endpoint or a terminal event. Componentwise `atol` arrays are supported. This exactly bounds X3: SciPy is a useful ODE baseline but supplies neither event completeness nor a DAE residual/mass contract.
2. **[SciPy 1.17 `gmres`](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.sparse.linalg.gmres.html), convergence/callback/maxiter sections.** Final convergence is tested on the true unpreconditioned residual `b-Ax`, while `callback_type='pr_norm'` reports a preconditioned residual each inner iteration and `maxiter` counts restart cycles (except legacy mode). Current ledgers must separately record cycles, inner iterations, reported/preconditioned residual and independently recomputed scaled true residual. SciPy GMRES is ordinary GMRES; use FGMRES only if the preconditioner truly varies within one linear solve.
3. **[SUNDIALS IDA Mathematics](https://sundials.readthedocs.io/en/latest/ida/Mathematics_link.html), initial-condition/nonlinear/rootfinding/linear-solver sections.** This is a design comparator, not a realized project dependency. IDA solves `F(t,y,ydot)=0`, requires consistent `(y0,ydot0)`, and its index-one initializer requires an explicit differential/algebraic partition and uniqueness of the algebraic state. Its Newton matrix is `F_y + alpha F_ydot`; nonfatal nonlinear failure reduces the step; constraints are checked after the nonlinear solve and also trigger step reduction. **Inference:** because the documented root search is principally sign-change based, even-multiplicity roots should not be assumed discoverable without an additional certificate. Large stiff Krylov solves generally require a problem-specific preconditioner approximating the iteration matrix. These are conditions on a completed residual, not evidence that the current split modules constitute that residual.

## Selected Program C: concrete mathematical and API design

### C1. Immutable problem, policy, and state contract

Introduce one deep-immutable `ProblemSpec` constructed only after copy-and-validate:

```text
ProblemSpec = {
  independent_coordinate: eta with orientation and units,
  clocks: [(operator, native_coordinate, native_rate_unit,
            d_eta_d_t, conversion_action, conversion_jvp)],
  variable_blocks: [(name, slice, unit, scale, domain, differential?, frame)],
  residual_blocks: [(name, slice, unit, owner, gross_terms)],
  F(eta,y,y_eta,context), JVP(v,dv), F_ydot/mass action,
  assembled_jacobian or abs_jacobian_scale_bound(s_y,s_ydot),
  event_functions and transition maps,
  invariant evaluators assembled independently of F,
  operator_generation, frame_generation, history_generation,
  physical_operator_id, source/data IDs, code/dependency identity
}

SolverPolicy = {
  kernel-specific typed subpolicies with no unknown/unconsumed fields,
  finite componentwise atol/rtol, row scaled-defect budgets,
  finite positive integer iteration/step bounds (bool rejected), PI controller state,
  separate event time/value tolerances and completeness policy,
  nonlinear/linear forcing and globalization policy,
  replay mode: exact-environment | portable-tolerance
}
```

Every suboperator declares its native clock, orientation and units. If a per-second rate `R_t` is placed in the increasing `eta=ln(a)` residual with `deta/dt=H`, then

\[
 y_\eta=R_t/H,\qquad
 D(R_t/H)[v]=DR_t[v]/H-R_t\,DH[v]/H^2.
\]

The conversion action and its JVP are first-class, finite-checked operators; no caller may divide by `H` ad hoc or silently mix `dt_s` with `deta`. Equivalent per-second and per-eta representations must give the same accepted physical endpoint, including a nonzero `DH[v]` control.

Arrays and mappings are recursively copied and validated, but NumPy read-only flags are not treated as an identity boundary: an owning array exposed to a caller can be made writeable again. Canonical primitive data therefore live in private byte-backed storage (or are copied on every public access), and derived caches carry the primitive digest that created them. Admission rehashes/revalidates primitive, derived and cross-field coherence. Construction must never change caller flags; public raw dataclass construction cannot bypass this path. The canonical commitment may be dual exposed hashes or one complete domain-separated aggregate hash; completeness and mutation sensitivity matter, not a dogmatic hash count.

The declared dependency manifest is checked against an independently maintained consumer/caller inventory and instrumented configuration-access trace. It includes registered event/callable implementation IDs and code digests, data/operator/policy/frame/history identities, binary library/BLAS identity, thread settings, CPU/runtime flags and replay mode. It is not generated from `ProblemSpec` itself. A `ProblemSpec` cannot infer clocks, frames, units, row ownership or algebraic roles from array position.

If implemented and V01/V02/V12 pass, this would address or fail-close R07--R12, R31, R40, R42, R45--R47, R52 and R55--R56 and provide a prerequisite for the remaining rows. It cannot invent the absent physics/data in R01--R06.

### C2. Residual, scale, rank, nullspace, and admission

Use one residual contract

\[
F(t,y,\dot y;P,H)=0,
\qquad J_\alpha = F_y + \alpha F_{\dot y},
\]

with square, named row/variable partitions and a declared differential/algebraic split. For each residual row, admit only if finite/domain gates pass and the **first-order componentwise scaled-defect certificate**

\[
\eta_i = \frac{|F_i|}
{s_{F,i}+\sum_j |(F_y)_{ij}|s_{y,j}
 +\sum_j |(F_{\dot y})_{ij}|s_{\dot y,j}}
\]

passes its typed budget, together with block WRMS/max norms and independently assembled physical invariants. This expression is not claimed to be an exact nonlinear componentwise backward error. It requires either an assembled sparse Jacobian or a separately implemented upper-bound action satisfying `B_y s >= |F_y|s` and `B_ydot s >= |F_ydot|s`; an ordinary JVP at `s` is invalid because cancellation can underestimate the absolute action. A remainder/validity-radius bound accompanies the first-order certificate. Linear subproblems separately use the usual componentwise backward-error certificate. `s_F`, `s_y`, and `s_ydot` carry units and physically meaningful floors; no unrelated global `max(...,1)` is permitted. Diagonal unit rescaling must leave every verdict unchanged, and V04 compares the denominator against an independent multiprecision/explicit-matrix oracle.

The DAE gate is local and explicit rather than inferred from a mask. It records the scaled rank of `F_ydot`, tests regularity of the square pencil `lambda F_ydot + F_y` over the declared segment, and, for a semi-explicit split `x'=f(eta,x,z), 0=g(eta,x,z)`, requires a nonsingular equilibrated `g_z`. Consistent initialization solves for the declared algebraic state and differential derivative and re-evaluates `F=0`. Pivoted QR/SVD supplies scaled rank/condition estimates over every declared current interpolation cell/trajectory sample, not only a manufactured fixture. Unsupported higher-index or irregular structure returns `HIGHER_INDEX_UNSUPPORTED`/`IRREGULAR_DAE`; it is never silently treated as index one. An orthonormal null basis is generated internally and `||Z^T r||` is a distinct compatibility gate. Singular/incompatible systems never silently switch to unconstrained least squares; a rank loss is a typed event/segment boundary.

Independent admission uses two separately assembled exchanges/updates. It cannot test an identity manufactured as `Q_atom=-Q_gamma`, nor define redshift work as the same difference it checks. `AdmittedStep` is created only by an admission service that re-evaluates the accepted endpoint under the committed problem/policy/generation and verifies residuals, domains, invariants, event endpoint and history candidate. Constructors for raw solver results are not public success constructors.

### C3. Closed trial-outcome taxonomy and fine-state adaptive controller

The step kernel must be nonautonomous and context-bound:

```text
ProblemOutcome = ReadyProblem | INCOMPLETE_PROBLEM | UNSUPPORTED_REGIME |
                 IRREGULAR_DAE | HIGHER_INDEX_UNSUPPORTED
TrialOutcome   = Candidate | RETRY_LTE | RETRY_NONLINEAR | RETRY_LINEAR |
                 RETRY_DOMAIN | NONFINITE_OUTPUT | ATTEMPT_BUDGET_EXHAUSTED |
                 FATAL_INVALID_PROBLEM
EventOutcome   = CERTIFIED_NO_EVENT | CERTIFIED_EVENT | EVENT_UNCERTIFIED |
                 SIMULTANEOUS_EVENT_UNRESOLVED | ZENO_UNRESOLVED |
                 EVENT_REINIT_FAILED
RemapOutcome   = REMAP_ACCEPT | INFEASIBLE_REMAP | REMAP_BUDGET_EXHAUSTED
AdmissionOutcome = AdmittedStep | REJECT_RESIDUAL | REJECT_INVARIANT |
                   REJECT_IDENTITY | REJECT_HISTORY
PublicationOutcome = PROMOTED | STAGED_REJECTED | CRASH_RECOVERED |
                     PUBLISH_IO_FATAL
```

Enums are exhaustive per stage. Retry outcomes may shrink and append finite attempt diagnostics but carry no committable state. `EVENT_UNCERTIFIED`, `INFEASIBLE_REMAP`, incomplete/unsupported/irregular problems and budget exhaustion are terminal for that segment unless an explicitly registered higher-level transition exists. They may serialize a diagnostic receipt, never an executable accepted restart or durable result. Only `AdmittedStep` may transition into a publication candidate, and only an admitted, fully gated generation may publish.

For backward-Euler step doubling, evaluate the full step at `t+h`, the first half at `t+h/2`, and the second half at `t+h`, all against the correct time-dependent operator. A history-dependent second half consumes an **ephemeral overlay** made from the first half's provisional dense/history segment:

```text
full  = trial(P, parent, eta, y, h)
half1 = trial(P, parent, eta, y, h/2)
overlay = parent.overlay(half1.dense_segment, provisional=True)
half2 = trial(P, overlay, eta+h/2, half1.y_end, h/2)
```

The overlay is identity-bound to the attempt, cannot be queried beyond its provisional endpoint, and is destroyed on rejection; it never mutates accepted history. Thus both paths approximate the same Volterra/delay problem. For order `p`, estimate

\[
e=\frac{y_{h/2,h/2}-y_h}{2^p-1}
\]

and, after all gates pass, advance with the fine `y_{h/2,h/2}` (not the coarse state and not an unchecked extrapolation). LTE-only acceptance uses a WRMS/max component norm. A PI law may update the next step using current and previous accepted LTE errors; rejected nonlinear, linear or domain outcomes force their own bounded shrink independent of an accidentally zero LTE. A domain failure may propose a feasibility-derived bound. Every retry has a finite hard attempt budget and preserves the parent bytes exactly.

Rejected attempts go to an attempt log but never update durable minima, maxima, history, controller memory, event generation, flux IDs or restart state. Only an `AdmittedStep` can commit.

If implemented and V05/V11/V12 pass, this would address R20--R24, R30, R32--R34 and R43--R44, including the X2 failure-representation contradiction.

### C4. Certified event transaction

Standard events are registered continuous functions `g_k(eta,y)` owned by `ProblemSpec`, not pre-supplied timestamps. A derivative-dependent event is unsupported unless the problem supplies a registered `DenseEventView` whose `ydot` is continuous on the whole segment. Discontinuous guards use a separately specified jump/transition contract and are invalid inputs to the continuous-root API. For each accepted dense segment:

1. evaluate finite endpoint values and use `signbit`/ordered comparisons, never the product `g_left*g_right`;
2. maintain separate dimensional budgets `g_atol_k`, `g_rtol_k`, `t_atol`, `t_rtol` and a separate root-deduplication rule;
3. issue a bracket certificate containing event/generation ID, endpoints, function values, dense-segment ID and monotonicity/completeness evidence;
4. refine a certified bracket; permit an event-landing substep below the ordinary integration `h_min` (or stop with a typed unresolved-event outcome);
5. collect all roots within the event-time equivalence budget; apply one registered combined transition or a declared deterministic priority. If neither is defined, return `SIMULTANEOUS_EVENT_UNRESOLVED`;
6. land at the event, record/admit a left-limit endpoint, apply the transition exactly once, record the right-limit state with a new generation, compute consistent `(y,ydot)`, reset invalid controller/multistep/Jacobian state, then resume;
7. persist pending brackets plus left/right state, priority/batch and transition receipts in history/restart;
8. treat a packet-speed zero crossing as a registered event and enforce an event-count/minimum-progress budget; suspected chattering/Zeno returns `ZENO_UNRESOLVED` without stepping through it.

Two sign changes within one step and even/grazing roots cannot be universally discovered from endpoints. Where physics supplies monotonicity, derivative extrema, a known root count or interval enclosure, use it. Simple monotone and declared-root-count validation cases **must** return certificates and show event-time convergence under step refinement; an implementation that always returns `EVENT_UNCERTIFIED` fails V06. Only cases outside the registered completeness regime may exhaust subdivision and return `EVENT_UNCERTIFIED`; never equate solver success with event completeness.

If implemented and V06/V12 pass, this would address R25--R29. R27 requires dense background evolution/equation-based roots rather than stored-knot surrogates. R28 validates inputs before zero-distance shortcuts and binds characteristic-face roots/restarts to the event transaction.

### C5. Stable kernels, derivative semantics, and nonlinear globalization

For constant transfer set `z=chi*t` and

\[
\phi_1(z)=\frac{1-e^{-z}}{z},\qquad
T=e^{-z}f_0+j t\phi_1(z).
\]

Evaluate `phi1` with `-expm1(-z)/z`; evaluate its derivative with an error-controlled series near zero,

\[
\phi_1'(z)=-\tfrac12+\tfrac z3-\tfrac{z^2}{8}
+\tfrac{z^3}{30}-\tfrac{z^4}{144}+\cdots,
\]

switching only when a remainder bound meets the requested floating-point budget. The JVP is

\[
\begin{aligned}
dT={}&e^{-z}\,df_0+t\phi_1\,dj\\
&+[-t e^{-z}f_0+j t^2\phi_1']\,d\chi\\
&+[-\chi e^{-z}f_0+j\phi_1+j t\chi\phi_1']\,dt .
\end{aligned}
\]

The analytic `chi=0` limit follows from the same series. Validate all primal and direction inputs before any zero-distance/zero-opacity return. Multiprecision value/JVP/second-difference sweeps across zero are mandatory.

Positive coordinates use log transforms without clipping. Before `exp`, candidate range/domain checks return a retryable line-search rejection; overflow is not allowed to escape or be clipped into a different iterate. Use one dimensionless merit definition for Newton, line search and final admission, with Armijo or a residual/constraint filter. Eisenstat--Walker forcing ties linear accuracy to nonlinear progress; iteration ledgers distinguish cycles, inner steps, preconditioned callback norms and true scaled residuals. Use FGMRES only if the preconditioner varies inside a solve.

Thermodynamic APIs distinguish partial and total derivatives, e.g. `partial_T_at_fixed_nH` from `total_T_along_background`, and carry density/remap derivative terms explicitly. Stable products use overflow/underflow-safe formulations. If implemented and V07/V09/V10 pass, these actions would address R32--R34, R39--R40 and the kernel portions of R54/R56.

### C6. Structure-aware fluxes, moving grids, and preconditioning

- Collision/transport assembly uses one immutable packet per **face, ordinate, velocity-sign interval and time segment**, not one scalar direction per side. Zero-speed crossings close one interval and are event-managed before direction changes. Equal-and-opposite residual rows may derive from one packet, while material and radiation state deposition are independently assembled and compared at admission.
